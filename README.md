# 研序 · 材料研究工作台

本地运行的个人研究工作台。围绕一个材料课题保存资料、查看原文证据、编辑报告，并保留生成与修改版本。

**当前版本：0.1.0 开发版。** 已接通真实本地存储和研究流程；真实模型质量评测尚未完成。没有密钥也可使用自编演示案例和手工写作。

## 启动

需要 Node.js 24.19 或更高版本。当前实际验证环境是 Windows、Node v24.19.0。

```powershell
npm ci
npm start
```

浏览器打开终端显示的地址，默认：

```text
http://127.0.0.1:4173
```

当前开发现场：旧 Demo 占用 4173，新工作台运行于 4174。这不是远程部署。

Windows 已安装依赖时，也可以在项目目录运行：

```powershell
.\Start-Workbench.ps1 -Port 4174
```

本次环境仅有 Codex 提供的 Node，`npm` 未在 PATH 中。已完成依赖安装；上面的启动脚本也会检查该本机运行时。正常安装 Node 的电脑按 `npm ci` / `npm start` 使用即可。

端口占用会明确报错；同一数据目录只能启动一个工作台，防止重复进程误判任务状态。

## 模型配置

将 `.env.example` 复制为 `.env`，填写：

```dotenv
OPENAI_API_KEY=你的密钥
OPENAI_MODEL=gpt-4.1-mini
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_ENDPOINT=responses
PORT=4174
MAX_MODEL_CALLS=16
MAX_RUN_MINUTES=10
```

停止旧工作台进程并重新启动后生效。`OPENAI_ENDPOINT=responses` 使用官方 Responses API；如果使用只兼容 OpenAI Chat Completions 的网关，可改成 `OPENAI_ENDPOINT=chat`，同时把 `OPENAI_BASE_URL` 改成该网关的 `/v1` 地址。模型需支持 JSON Schema 输出；这里的默认值延续旧项目，不宣称是最新或效果最优模型。

使用 AI Jump 一类 OpenAI 兼容网关时，通常写法类似：

```dotenv
OPENAI_API_KEY=你在网关生成的令牌
OPENAI_BASE_URL=https://aijump.cc/v1
OPENAI_ENDPOINT=chat
OPENAI_MODEL=网关文档或控制台里的模型名
```

如果该网关明确支持 `/v1/responses`，也可以把 `OPENAI_ENDPOINT` 改为 `responses`。

密钥只由服务端读取，不发送到浏览器。设置页的“检查连接”查询模型可访问性，不进行报告生成，也不能保证真实生成一定成功。

## 已实现

- 项目库：创建、搜索、编辑、归档与恢复。
- SQLite 保存项目、工作草稿、报告版本、资料索引、证据和运行记录。
- 原文：粘贴文字、抓取公开 HTML / 纯文本，保存不可变文本快照；失败来源有明确状态。
- 报告：章节阅读与编辑、防抖保存、冲突检测、另存版本、本机意外恢复草稿。
- 引用：原文位置、来源信息、人工审核；编辑相关内容后重置审核状态。
- AI 流程：确认计划、可选网页检索、分章节生成、结构与引用检查、生成候选版本。
- 恢复：取消、进程中断识别、继续失败步骤、调用次数与累计时间上限。
- 版本：比较候选与当前草稿，采用前保留旧版；Markdown 导出与带证据的打印。
- 前端：独立项目视图、章节目录、证据侧栏、窄屏适配、键盘焦点返回。

## 日常使用

1. 创建研究课题，填写材料、研究问题、范围及需要的章节。
2. 在资料页添加原文，或在研究计划中启用公开网页搜索。
3. 配置模型后确认计划；在执行记录查看阶段、失败原因和用量。
4. 查看生成的候选报告，与当前草稿比较，决定是否采用。
5. 点击原文引用核对，修改章节，保存版本或导出 Markdown。

不使用模型时，在报告页创建写作草稿即可手工编辑。

演示项目包含自编材料、原文与报告，始终保留“演示数据”标识；不会假装进行了联网研究。

## 架构

```text
浏览器（原生 JavaScript + CSS）
                ↓
本机 Node.js HTTP 服务
    ├── 项目 / 草稿 / 版本
    ├── 正文采集 → 证据 → 章节生成 → 引用检查
    ├── 运行记录 / SSE / 取消与恢复
    └── SQLite + 原文文件
```

入口是 `workbench.mjs`、`workbench.html` 和 `ui/`。原 `index.html`、`server.mjs`、`src/` 保留为旧 Demo；正式工作台不会通过 HTTP 暴露旧服务源码或数据目录。

## 当前限制

- 没有配置真实模型密钥，本轮未完成真实模型端到端核验或研究质量基线对比。
- 搜索依赖 Bing RSS，可用性和内容质量不作保证；网页可能被 403、验证码、登录要求或网络阻断。可手动粘贴原文继续。
- 当前支持 HTML 与 UTF-8 纯文本；PDF、扫描件 OCR、复杂表格、DOCX、语义检索、多模型均未实现。
- 证据检查保证引用可定位、ID 合法，不能保证原文支持结论；数字检查只是提示，统计口径仍需人工核对。
- 首版采用每章最多 18 个文本块的简单相关度选择，可能遗漏长文信息，不宣称已经实现专业 RAG。
- 单个来源最多 200,000 字符；一轮最多 12 个来源；超时或取消的外部调用仍可能产生费用。
- 当前每章以段落为审核单位，尚未拆到每条独立事实；数值的单位、区域与年度自动冲突比对仍待实现。

## 数据与备份

项目数据在 `data/`。备份前停止工作台，然后整体备份该目录；不要只拷贝 SQLite 主文件而遗漏 WAL 或原文文件。

本地运行不等于完全离线：搜索会发送检索词，模型会收到课题和选中的原文片段。工作台不主动上传整个本地资料库。

`.gitignore` 排除密钥、数据库、生成资料、日志、无关 `output/` 和 `node_modules/`。公开前还应检查暂存内容；第三方报告全文不随仓库分发。

项目尚未选择开源许可证，也未创建或发布远端仓库。正式公开前由项目所有者确认许可。
